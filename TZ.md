# Техническое задание

## Цель

Разработать клиентское приложение для двухэтапного подбора автозапчастей через Web-сервис «Проценка» Favorit Parts. Источник контракта API: [официальная документация](https://lk.favorit-parts.ru/static/wsprice.pdf), редакция от 06.03.2023.

## Функциональные требования

1. Пользователь вводит артикул. После прекращения ввода выполняется первый запрос с `number` и ключом покупателя `key`.
2. Из полученных товаров `goods` выводится список уникальных производителей `brand`. Если товаров нет, показывается сообщение об отсутствии результатов.
3. Пользователь выбирает производителя. Выполняется второй запрос с `number`, `brand`, `key` и `analogues=on`.
4. Отображаются найденная деталь и аналоги из `goods.analogues`. Каждое складское предложение выводится отдельной строкой с названием, производителем, артикулом, ценой склада `warehouses.price`, остатком склада `warehouses.stock` и складом.
5. Во время обоих запросов показываются индикаторы загрузки. Ошибка сервиса, сетевая ошибка и пустой результат отображаются в интерфейсе. Для ошибок доступно повторение запроса.
6. Изменение артикула сбрасывает выбранного производителя и прежние предложения.

## Технические требования

- React без TypeScript, Redux Toolkit и React Redux.
- Адаптивный интерфейс с CSS.
- Ключ покупателя хранится только на сервере в `FAVORIT_API_KEY` и не публикуется в репозитории и браузерном коде.
- Серверный прокси обращается к документированному `http://api.favorit-parts.ru/hs/hsprice/` и передаёт ответ клиенту в JSON. Адрес и протокол взяты из документации.
- Параметры запроса кодируются через `URLSearchParams`.
- Цена верхнего уровня `goods.price` не используется: документация требует брать цену конкретного склада.
- Формат `goods` и `analogues` обрабатывается как массив или одиночный объект, поскольку в описании указан массив, а в иллюстрациях ответа показан объект.

## Критерии приёмки

- Ввод артикула приводит к загрузке производителей; выбор производителя — к загрузке аналогов.
- В каждой строке результата видны название/производитель, цена и остаток. Отсутствующая цена обозначена прочерком и не подменяется ценой товара.
- Пустой ответ, ответ с `error` и сбой сети не ломают страницу.
- Проект устанавливается, проходит тесты, собирается и запускается по инструкции в README.

## Условие для проверки на реальном API

Нужен действующий ключ покупателя Favorit Parts. Без него можно проверить сборку, интерфейс и обработку данных на тестовых примерах, но нельзя подтвердить фактический ответ сервиса и его доступность из выбранной сети.
